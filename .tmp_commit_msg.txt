refactor(cmd/htsfile): split CLI by subcommand + per-subcommand tests (v0.17.0)

Closes the architecture review's item #2: bring the CLI
from a 0.21× test ratio to its own per-subcommand files
with their own _test.go.

Before:
  main.go                       2046 lines,  64 funcs
  cmd/htsfile test ratio         0.21×

After:
  main.go                        796 lines,  36 funcs
  cmd/htsfile test ratio         0.35×
  (climbing toward the >= 0.6× target of the review)

The per-format runCheck* / runRoundtrip* / runSummary*
families move into dedicated files:
  - check.go      (366 lines)  — runCheck + 11 helpers
  - roundtrip.go   (353)       — runRoundtrip + 11 helpers
  - summary.go     (439)       — runSummary + 11 helpers
                                  + bedTypeFromColumns
  - report.go      (260)       — reportSeverity / reportIssue
                                  + runIssueReport + 8 adapters

main.go stays the orchestrator: main, usage,
format-detection, sniffing, dispatch, and the
translate / vcfquery / vcfindex paths. The 43 functions
moved out preserve their signatures byte-for-byte; the
wire output is unchanged.

New file cmd/htsfile/cli_test.go (458 lines) with three
test families:
  - runCheck* / runRoundtrip* / runSummary* per format
    (clean records);
  - runCheckVCF strict-mode rejection;
  - dispatch tests that exercise runCheck / runRoundtrip
    / runSummary through tempfile format detection;
  - a coverage-shim test that forces the build to fail if
    any of the eight reportFrom* adapters is removed.

The split also opened room for consolidation: each
per-format helper now lives next to its own future tests
(rather than buried inside a 2 kLoC god file).

Remaining from the review:
  - split vcf/validate.go (item #1)
  - document Validator streaming-state footgun (item #3)
  - consolidate translate.go symmetric pairs (item #4)
  - add CLI pipeline integration test (item #5)

go test -race -count=1 ./... is green; golangci-lint
run ./... reports 0 issues; make fmt-check is clean.
