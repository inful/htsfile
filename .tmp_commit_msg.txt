chore(bcf): per-type MISSING sentinels for Integer/Float FORMAT (T4.24, v0.16.1)

Closes the last §5 BCF2 gap. Per §BcfTypeEncoding
line 2304 / 2333:

  - Integer MISSING = 0x80000000 (the first of the
    eight reserved values just above math.MinInt32).
  - Float MISSING = 0x7F800001 (signaling NaN,
    distinguished from END_OF_VECTOR 0x7F800002).

The previous writer (v0.16.0) encoded missing Float /
Integer slots via the size-0 `typeMissing` byte
(spec-compliant but not the per-type form). Some
external tools emit the per-type sentinel; this
release adds symmetric handling on the read path and
moves the write path to the per-type form so files
round-trip cleanly with htslib / pysam.

Changes:

- bcf/end_of_vector.go: new constants
  bcfFloatMissing (0x7F800001) and bcfIntMissingInt32
  (0x80000000) keep the spec's reserved sentinels
  alongside the existing END_OF_VECTOR constants.

- bcf/format.go:
  * writer: per-type MISSING for Integer / Float
    missing slots;
  * reader: detects either size-0 typeMissing
    (whole-field) or per-type MISSING
    (per-sample slot) and surfaces Missing=true on
    the corresponding sample.

- bcf/format_test.go: TestFormatFloatMissingSignalingNaN
  and TestFormatIntMissingSentinel cover mixed
  missing/present slots.

§5 BCF2 of vcf/SPEC_COMPLIANCE.md is now
spec-compliant.
