refactor(vcf): split validate.go into four domain-keyed files (v0.18.0)

Closes the architecture review's item #1. The old
vcf/validate.go was a 3,172-line god module — 100
exported symbols, 49 of 162 commits (~30% of the repo's
history) touched it, and every SPEC_COMPLIANCE.md
task numbered T-number added more code to the same
file. The split is mechanical (no behaviour change)
and groups rules by domain:

  validate.go           752 LoC  orchestrator (Validator
                                  struct + lifecycle:
                                  New, WithReference,
                                  Validate, Reset,
                                  HeaderChecks, Next,
                                  Finish; checkHeader,
                                  checkRecord)
  validate_record.go    571 LoC  record-level rules
                                  (checkEventType,
                                  checkPhaseStyle,
                                  checkPloidy, checkEND,
                                  checkENDBounds,
                                  checkGVCFBlock,
                                  checkGVCFBlockRef,
                                  checkSVLENBounds,
                                  checkSVClaim,
                                  checkFilter,
                                  checkBreakendPositions,
                                  checkRefMatchesReference)
  validate_info.go      530 LoC  INFO-level rules
                                  (checkInfo plus its
                                  helpers, including
                                  the rn-determined-keys
                                  machinery and the
                                  SV-CLAIM helpers)
  validate_samples.go  1,347 LoC  per-sample/FORMAT block
                                  (checkSamples plus
                                  the GT/ploidy/LAA/PSL/
                                  PSO/MATEID layer)

Largest functions are now in their right-sized files:
  checkInfo        247 LoC (validate_info.go)
  checkSamples     242 LoC (validate_samples.go)
  checkRecord      196 LoC (validate.go)
  Next             181 LoC (validate.go)
  checkRNDet.      118 LoC (validate_info.go)

Each new file gets a minimal `package vcf` +
imports header that matches what its contents actually
reference (fmt, strings, regexp, strconv, math as
needed). The orchestrator's `Validator` struct,
helper types, and lifecycle methods are the only
file-level state; everything else is reachable
through regular package-internal function calls.

The split also opens room for consolidating duplicated
helpers (Next/Validate share ~180 lines of header
loading, record loop, validation entry, and footer).

go test -race -count=1 ./... is green; golangci-lint run
./... reports 0 issues; make fmt-check is clean.
