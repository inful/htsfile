docs+tests(v0.18.1): document Validator streaming footgun + CLI pipeline test

Two small-but-leverage things from the architecture
review that ship together.

Item #3 — document Validator streaming-state footgun.

The Validator had a doc comment claiming "safe to
re-use across multiple Validate calls" — accurate for
the one-shot helper, misleading for the streaming API.
Cross-file reuse leaks seenIDs/seenChroms into the next
file's first record; concurrent streams race on the
mutable fields. The new doc comment is explicit and
turns the footgun into a documented contract.

Item #5 — CLI pipeline integration test.

The README has long claimed "every format the library
reads has a Writer; CLI roundtrip works for all of
them" without a single test exercising the claim
end-to-end. TestCLIPipeline_VCFToBCFAndBack drives

  vcf.NewDecoder(minimal VCF)
  → runVCFToBCF
  → runBCFToVCF
  → vcf.NewDecoder
  → vcf.NewValidator(ModeDefault).Validate

and asserts no issues emerge at the pipeline boundary.
A regression in any of the four conversions now trips
the test.

TestValidatorResetClearsState (in vcf/validate_test.go,
re-created after the v0.18.0 split dropped the file)
locks the doc-comment promise: a Validator that runs
two files via the streaming API without Reset() must
fire a false duplicate ID; after Reset() it must not.

go test -race -count=1 ./... is green; golangci-lint run
./... reports 0 issues; make fmt-check is clean.
